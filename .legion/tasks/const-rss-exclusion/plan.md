# Const RSS Exclusion

## Goal
Ensure any document served under the `/const` path family is excluded from public feed output. In this repository the feed output is currently Zola-generated Atom (`atom.xml`), but the task treats the user-facing "RSS" requirement as all public site feeds generated by the build.

## Problem
`/const` is now protected by Cloudflare Access, but Zola can still include dated content in generated feeds unless feed rendering excludes it. A private or access-controlled path must not leak titles, links, summaries, or body content through `atom.xml` or taxonomy feeds.

## Acceptance Criteria
- No generated feed contains an entry whose URL path is `/const` or starts with `/const/`.
- The current `content/const.md` page is excluded from feed output.
- Future pages under the `/const` path family are excluded by a reusable rule, not by a one-off generated output edit.
- Normal public blog/diary/gcores feed entries remain unaffected.
- `zola build` passes and verification records direct checks against generated feed files.
- Legion verification, review, walkthrough, wiki writeback, and PR lifecycle complete.

## Assumptions
- The repository's current Zola feed filename is `atom.xml`; users may still colloquially call it RSS.
- `/const` path family means the exact `/const` page plus any descendant path below `/const/`.
- The content should remain published and protected by Cloudflare Access; this task only changes feed exposure.

## Constraints
- Do not disable all feeds.
- Do not remove `/const` navigation, content, or Cloudflare Access configuration.
- Do not change public URLs for existing content.
- Do not expose private `/const` content in task docs, feed snapshots, or PR text.

## Risks
- Zola built-in feed templates may not support a front matter flag for exclusion, so the solution may need a local feed template override.
- Multilingual and taxonomy feeds can diverge from the root feed if only one template or filename is checked.
- A path filter that is too broad could accidentally remove public content; a path filter that is too narrow could leak descendant `/const/` pages.

## Scope
- Zola feed template/config/front matter changes needed to exclude `/const` path entries.
- Build-time verification that generated feeds do not include `/const` URLs.
- Legion task docs and wiki summary for the feed privacy pattern.

## Non-goals
- Do not add new Cloudflare resources or change Access policy.
- Do not implement authentication-aware feeds.
- Do not change feed format from Atom to RSS or add additional feed filenames.
- Do not redesign the `/const` page or navigation.

## Recommended Direction
Use a template-level exclusion rule for generated feeds, keyed on output path and optionally supported by page front matter metadata. This is safer than relying on a nonexistent Zola `in_feed` flag or removing dates, and it protects both the current `/const` page and future descendants.

## Phases
1. Contract and context: create this task and confirm Zola feed behavior.
2. Implementation: add the minimal feed exclusion mechanism.
3. Verification: build the site and assert generated feeds contain no `/const` entries while public feed entries remain.
4. Review and delivery: run review-change, report-walkthrough, legion-wiki, and PR lifecycle.
